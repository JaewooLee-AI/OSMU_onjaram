## 🔴 높음 — 먼저 고칠 것

### H1. 확인 없이 바로 지워지는 삭제 버튼
| 위치 | 지우는 것 |
|---|---|
| 워크벤치 맨 위 🗑 아이콘 (`workbench_view.py:235`) | **지금 글 전체**. [➕ 새 콘텐츠] 바로 옆이라 잘못 누르기 쉽습니다 |
| 대시보드 '실패한 작업'의 [🗑️ 삭제] (`dashboard_view.py:143`) | 글 |
| 설정 → LLM 벤더·네이버 API의 삭제 (`settings_view.py:275, 477, 604`) | **저장한 API 키**(다시 입력해야 함) |
| 설정 → 카드 종류·디자인의 지우기 (`card_types_view.py:229, 308`) | 사용자가 만든 카드 종류·디자인 |
| 브랜드 킷 → [제목 이력 전체 삭제] (`brand_kit_view.py:570`) | 제목 반복 방지 이력 |

보관함·네이버 게시 화면의 삭제와 대시보드 '콘텐츠 초기화'에는 확인 창이 있습니다. 화면마다 동작이 달라서 더 위험합니다.

- **제안**: 모두 확인 창을 띄웁니다. 글 삭제는 '보관'을 먼저 권합니다(보관함과 같은 문구).

### H2. 생성이 끝나면 사용자를 카드·쇼츠 화면으로 강제로 옮김
- [만들기]가 끝났을 때 카드나 쇼츠가 체크되어 있으면 무조건 카드·쇼츠 화면으로 넘어갑니다(`workbench_view.py:764`).
  1. **블로그와 함께 만들면 방금 완성된 블로그 글을 볼 기회가 없습니다.** 완료 안내와 주의 사항(누락 정보, 쇼츠 영상은 따로 만들기 등)도 0.8초 만에 사라집니다.
  2. 생성은 수십 초 걸립니다. 그동안 **다른 메뉴(설정 등)로 가 있어도, 끝나는 순간 카드·쇼츠 화면으로 끌려갑니다.**
- **제안**:
  - 블로그를 포함해 만들었으면 워크벤치에 남고, 맨 위에 완료 상자를 둡니다. 예: "블로그·카드뉴스 5장·쇼츠 대본을 만들었습니다 → [🃏 카드·쇼츠에서 보기]".
  - 카드·쇼츠만 만들었고 사용자가 아직 워크벤치에 있을 때만 이동합니다.

### H3. 저장하지 않은 수정이 메뉴를 옮기면 조용히 사라짐
- **카드·쇼츠 ② 다듬기**: 제목·내용·아래 한 줄을 고친 뒤 [적용]을 누르지 않고 왼쪽 메뉴로 이동하면 수정이 사라집니다(`studio_view.py:416`). 다른 카드로 넘기거나 글을 바꿀 때만 저장됩니다.
- **워크벤치 본문**: 본문·태그는 각 탭의 [저장]을 눌러야 반영됩니다. 메뉴를 옮기면 경고 없이 사라집니다.
- **브랜드 킷**: [킷 저장]과 [회사 공통 저장] 버튼이 따로 있습니다. 한쪽만 누르면 다른 쪽 수정은 사라집니다.
- **제안**:
  - 칸을 벗어날 때(blur) 자동으로 저장합니다(카드 문구·쇼츠 대본).
  - 본문처럼 큰 글은 '저장 안 한 수정이 있습니다' 표시를 두고, 메뉴를 옮길 때 묻습니다.

### H4. 화면마다 '지금 작업 중인 글'이 다름
- 앱이 기억하는 '현재 글'이 없습니다. 메뉴로 들어갈 때마다 화면이 각자 글을 고릅니다.
  - 워크벤치는 가장 최근 글(빈 '제목 없음' 초안인 경우가 많음)을 엽니다.
  - 카드·쇼츠는 카드가 있는 첫 글을 엽니다.
  - 점검 중에도 실제로 작업하던 글이 아니라 빈 초안이 열렸습니다.
- **제안**: `AppState`에 현재 글 하나를 두고 워크벤치·카드·쇼츠·네이버 게시가 함께 씁니다. 글을 고르면 갱신하고, 메뉴로 들어오면 그 글을 엽니다.

### H5. 직접 고친 블로그 본문을 확인 없이 덮어쓰는 다시 만들기
- 결과 아래 [🔁 초안 다시 생성]과 접힌 메모·설정 안의 [만들기]는 확인 없이 본문을 새로 씁니다. [만들기]는 카드도 새로 기획합니다.
- 카드·쇼츠 화면의 [카드 만들기]는 "고친 내용이 바뀝니다" 확인 창을 띄웁니다. 워크벤치만 없습니다.
- 다시 만들기 버튼이 두 곳에 있고 하는 일도 달라 헷갈립니다. [초안 다시 생성]은 블로그만 다시 만들고, [만들기]는 고른 산출물 전부를 다시 만듭니다.
- **제안**:
  - 버튼을 하나로 합칩니다(무엇을 다시 만들지 고르게).
  - 본문이나 카드를 고친 적이 있으면 확인 창을 띄웁니다.

## 🟠 중간 — 흐름·실수 방지

### M1. 검수(컴플라이언스) 실패 글도 바로 게시 대기열로 갈 수 있음
- [🚀 네이버 게시 대기열로]는 검수 결과를 보지 않습니다(`workbench_view.py:803`).
- 검수 결과는 결과 화면 맨 아래, 긴 보고서 속에 있습니다. 상담 윤리(치료·효과 보장 표현 등)가 중요한 회사라 위험합니다.
- **제안**:
  - 검수 실패나 미해결 항목이 있으면 버튼을 누를 때 "확인하고 넣기" 창을 띄웁니다.
  - 검수 요약(점수·미해결 개수)을 결과 맨 위로 올립니다.

### M2. 카드·쇼츠만 만든 글은 상태가 영원히 '소재 대기'
- 블로그 없이 카드나 쇼츠만 만들면 상태가 바뀌지 않습니다(`outputs.py`).
- 대시보드에서 아직 아무것도 안 한 글처럼 보이고, 만드는 동안 '생성 중' 표시도 없습니다.
- **제안**: 카드를 그리면 '초안 완료'(또는 '카드 완료')로 바꿉니다. 만드는 동안은 '생성 중'으로 두고, 중간에 실패하면 '실패'로 남깁니다.

### M3. 삭제·초기화 뒤에 파일이 남음
- 글을 삭제하면 DB 줄만 지웁니다(`repo.delete_campaign`). 그 글의 다음 파일은 그대로 남아 용량을 차지합니다.
  - 카드 그림
  - AI 이미지(돈을 내고 만든 것)
  - 쇼츠 영상
- '콘텐츠 초기화'도 올린 사진만 지우고 `exports`(카드·쇼츠·AI 이미지) 폴더는 남깁니다.
- 대시보드 용량 표시에도 잡히지 않습니다.
- **제안**:
  - 삭제할 때 그 글의 파일도 함께 지울지 묻습니다. 보관함에 있는 '용량 정리' 기능을 재사용하면 됩니다.
  - 초기화 범위에 `exports`를 넣습니다.

### M4. API 키 입력이 두 곳으로 나뉨
- 키는 '🔑 LLM 벤더' 탭에서 '연결 테스트용 모델 ID'를 직접 써서 저장합니다. 모델과 단가는 '🤖 모델 등록' 탭의 간편 설정에서 다시 키를 넣고 불러옵니다.
- 처음 쓰는 사람에게는 순서가 헷갈립니다(실제로 질문이 있었던 부분).
- **제안**: 첫 탭을 '🔑 AI 연결(간편)'으로 합칩니다. Google 키를 한 번 넣으면 연결 확인, 모델·가격 불러오기, 적용까지 끝나게 하고, 벤더별 수동 입력은 '고급'으로 접습니다.

### M5. 결과 화면 정보가 너무 많고 순서가 중요도와 다름
- 결과 화면 구성
