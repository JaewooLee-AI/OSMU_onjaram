# FFmpeg 동봉 (Windows 설치형)

쇼츠 영상(`cards/shorts_renderer.py`)은 FFmpeg·ffprobe로 이미지를 이어 붙이고 음성과 합쳐 MP4(H.264 + AAC)를 만듭니다.
앱을 설치하는 직원 PC에 FFmpeg가 따로 없으므로 **설치 프로그램에 함께 넣습니다.**

## 찾는 순서 (`cards/ffmpeg_tools.py`)
환경변수 `OSMU_FFMPEG_DIR` → `<앱>/cards/bin/` (설치본: 워크플로가 여기에 복사) → `%APPDATA%\OSMU_ONJARAM\bin\` → PATH.
없으면 쇼츠 탭이 "FFmpeg를 찾을 수 없습니다"라고 알리고 영상 만들기를 막습니다(카드뉴스·블로그는 영향 없음).

## 어떤 빌드를 넣을까 — **결정(2026-11-06): LGPL 빌드로 진행**
화질이 부족한 PC가 나오면 GPL 빌드로 바꿀 수 있습니다(그때는 소스 제공 의무를 다시 검토).
| | LGPL 빌드 (현재 워크플로) | GPL 빌드 (gyan.dev, BtbN `-gpl`) |
|---|---|---|
| H.264 인코더 | `libx264` 없음 → `libopenh264` 또는 Windows `h264_mf`로 대체 | `libx264` (화질·속도 좋음) |
| 배포 의무 | LGPL: 라이선스 문구·소스 입수 방법 고지, 사용자가 교체 가능해야 함(별도 실행 파일이라 충족하기 쉬움) | GPL: 라이선스 전문과 **해당 빌드의 소스 제공(또는 서면 제안)** 필요 |
| 화질 | `h264_mf`는 PC 환경(하드웨어 인코더)에 따라 달라질 수 있음 | 안정적 |

- 앱은 FFmpeg를 **별도 프로그램으로 실행**(subprocess)할 뿐 링크하지 않습니다. 그래도 FFmpeg 실행 파일을 재배포하므로 해당 라이선스의
  고지 의무는 따릅니다. 공개 저장소·무료 배포라 부담이 작지만 **정확한 의무는 사용하는 빌드의 라이선스 문서로 확인**하세요(저는 법률 자문이 아닙니다).
- 현재 워크플로(`Bundle FFmpeg`)는 LGPL 빌드를 받아 `app/cards/bin/`에 복사하고, 빌드 때마다 인코더 존재와 시험 인코딩을 확인합니다
  (실패하면 빌드가 멈춥니다). **이 스텝은 아직 CI에서 실행해 본 적이 없으므로** 첫 실행에서 다운로드 URL, zip 폴더 구조, 인코더 목록을 확인하세요.
- `latest` URL은 시간이 지나면 내용이 바뀝니다. 안정화되면 특정 릴리스 주소로 고정하고 SHA256(워크플로 로그에 출력됨)을 기록하세요.

## 설치본에서 확인할 것 (로컬 검증)
1. 설치 후 `C:\Program Files\OSMU Onjaram\app\cards\bin\ffmpeg.exe`가 있는지.
2. 앱의 🎬 쇼츠 영상 탭에 FFmpeg 경고가 없고, 영상이 만들어지는지(음성은 Gemini 키 또는 무료 음성).
3. 만든 MP4가 휴대폰(인스타그램·유튜브)에서 재생되는지.
4. `h264_mf`를 쓰게 되는 PC에서 화질이 충분한지(아니면 GPL 빌드로 전환).

## 라이선스 고지
앱 설치 폴더의 `cards/bin/`에 FFmpeg의 LICENSE·README를 함께 둡니다(워크플로가 복사). 앱 안에서 보여 줄 "오픈소스 라이선스" 화면은 아직 없습니다.
